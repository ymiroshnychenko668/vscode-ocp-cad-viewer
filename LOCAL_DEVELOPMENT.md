# Запуск из локальных форков

`run-local.sh` использует Python-код из этого репозитория и собранный фронтенд
из соседнего `../three-cad-viewer`. Python-зависимости берутся из общего `../.venv`;
установленный там пакет не заменяется. Для обоих Python-процессов используется
абсолютный `PYTHONPATH`, а JS/CSS сервируются через ссылки на локальный `dist/`.

Первичная сборка фронтенда (запускается из этого каталога):

```bash
cd ../three-cad-viewer
yarn install --frozen-lockfile
```

Install выполняет `prepare` со сборкой. После изменений TypeScript/CSS:

```bash
yarn build
```

Запуск из `cad-viewer/` на свободном порту:

```bash
./run-local.sh '../wall case for display' --no-browser --port 3940
```

У проекта корпуса `../wall case for display/run.sh` вызывает эту же команду.
Просмотр: <http://127.0.0.1:3940/viewer>. Перед повторным запуском завершите текущий
процесс этого просмотрщика через Ctrl+C. Другие экземпляры не останавливаются.
Изменения CAD-модели перечитываются автоматически. После сборки фронтенда обновите
вкладку браузера; после изменения Python-сервера перезапустите эту команду.
Шаблон `resources/viewer.html` синхронизируется при каждом запуске.

При старте выводятся фактический путь импорта `ocp_vscode` и путь фронтенда.
Текущие версии клонов: Python-интеграция 4.0.1, фронтенд 5.0.5.
Закреплённая npm-зависимость 5.0.1 для обычной upstream-сборки не изменена:
этот запуск явно использует локальный фронтенд.

Дополнительные параметры окружения: `CAD_VIEWER_PYTHON` — путь к Python,
`CAD_VIEWER_FRONTEND` — путь к клону фронтенда. Они не обязательны при стандартном
расположении двух репозиториев рядом с CAD-проектами.

## Метаданные STEP

Общая библиотека импорта находится в `../step-metadata` и устанавливается
в рабочее окружение как editable-пакет:

```bash
uv pip install --python ../.venv/bin/python --no-deps -e ../step-metadata
```

В модели замените импорт на `from step_metadata import import_step`.
Полный исходный документ XDE доступен через `load_step`; исходный файл не меняется.
Форк автоматически передаёт JSON-словарь `shape.cad_metadata` вместе с геометрией.
Это также работает для собственных моделей, которым словарь задан в Python.
Отдельный импорт `step_metadata` внутри самого viewer не требуется.

Карточка выбранного компонента находится во вкладке «Свойства» нижней левой
панели, рядом с прежним «Журналом». Компонент можно выбрать в дереве или щелчком
по модели. «Копировать ссылку» копирует идентификацию компонента для обсуждения.
Исходный ID относится к определённой версии STEP; для повторных экземпляров
одной детали в проекте задавайте отдельный `instance_id`.

Произвольные метаданные поддерживаются как вложенные JSON-значения. Поля
`original`, `source`, `properties`, `current`, `coverage` выводятся отдельно.
Просмотр не означает, что эти поля автоматически попадут в STEP при штатном
вызове `build123d.export_step()`.

Проверка передачи данных без подключения к работающему viewer:

```bash
OCP_VSCODE_PYTEST=1 PYTHONPATH=. ../.venv/bin/python -m pytest tests/test_metadata.py tests/test_show.py -q
```
